# Опис властивостей та методів EasyBusyChat API

Документ містить довідник властивостей, синхронних та асинхронних методів зовнішньої компоненти **EasyBusyChat** (Native API) для **1С:Підприємство / BAS**, а також опис обробки подій (`GetLastEvent` та `ExternalEvent`) і механізму `reqId`.

---

## 3. Генерація подій та відмінності між Pull і Push (ExternalEvent)

Компонента підтримує два способи отримання подій у 1С:

### 3.1. Режим Pull (`GetLastEvent`)
Метод `GetLastEvent()` повертає **повний конверт події** у вигляді JSON-рядка:
```json
{
  "event": "chat_action",
  "payload": {
    "actionId": "view_contact",
    "reqId": 1,
    "chatId": "12345678",
    "provider": "telegram",
    "accountId": "403562eb-744e-487f-8b4c-80369e18f2b5"
  }
}
```

### 3.2. Режим Push (`ExternalEvent` / `ЗовнішняПодія`)
При виклику `SetPushEventsEnabled(true)` події надсилаються безпосередньо в обробник платформи 1С:
`Процедура ОбработкаВнешнегоСобытия(Джерело, Подія, Дані)` / `ЗовнішняПодія`:

- **`Джерело` (Source)**: Завжди рядок `"EasyBusyChat"`.
- **`Подія` (Event)**: Назва події (наприклад, `"chat_action"`, `"chatOpened"`, `"commandResult"`, `"notification"`).
- **`Дані` (Data)**: **Плоский JSON-рядок `payload`** (розпакований вміст поля `payload`, де вже міститься `reqId`).

Приклад значення параметра `Дані` для події `chat_action`:
```json
{
  "actionId": "view_contact",
  "reqId": 1,
  "chatId": "12345678",
  "provider": "telegram",
  "accountId": "403562eb-744e-487f-8b4c-80369e18f2b5"
}
```

## 4. Двосторонній обмін з `reqId` (Запит — Відповідь)

Коли користувач натискає дію в меню чату (наприклад, «Переглянути контакт», «Створити угоду»), інтерфейс чату надсилає запит до 1С та очікує відповіді:

1. **UI генерує подію `chat_action`** з унікальним числовим `reqId` (наприклад, `reqId: 1`) та `actionId`.
2. **1С / BAS отримує подію** через `ExternalEvent` або `GetLastEvent()`, розбирає JSON і виконує бізнес-логіку.
3. **1С повертає результат через `PostMessage`**, обов'язково вказуючи той самий `reqId` та `event: "action_result"`:

```bsl
// Успішне виконання дії:
ВідповідьJSON = "{""event"":""action_result"",""reqId"":" + Формат(ReqId, "ЧГ=0") + ",""success"":true,""payload"":{}}";
ЧатКомпонента.PostMessage(ВідповідьJSON);

// Відхилення або помилка виконання:
ВідповідьJSON = "{""event"":""action_result"",""reqId"":" + Формат(ReqId, "ЧГ=0") + ",""success"":false,""error"":""Контакт не знайдено в базі 1С""}";
ЧатКомпонента.PostMessage(ВідповідьJSON);
```

## 6. Уточнення контракту після аудиту 2026-09-09

- Legacy Булево означає прийняття в чергу. `completed` для загальних команд означає підтвердження UI після застосування обробника; відсутність підтвердження завершується `command_ack_timeout`. OpenChat додатково очікує відповідний chatOpened. ExecuteScript підтверджує синхронний eval; довільні майбутні Promise/таймери скрипта не очікуються. ShowTestNotification підтверджує обробку запиту, а не появу системного popup.
- `CancelOperation` не відкочує вже застосовану команду. Для running-операції одразу встановлюється `result.outcomeUnknown=true`. Якщо POST міг дійти до сервера, перед повтором потрібна звірка (`reconcileBeforeRetry`). Уже виконуваний синхронний виклик WinHTTP завершується за власним тайм-аутом; наступні запити перевіряють cancellation/deadline.
- При помилці після успішного пошуку/створення контакту результат містить `contact`, `contactCreated`, `opened:false`. Не створюйте цей контакт повторно без перевірки.
- Init відхиляє непідтримуваний apiBaseUrl з `invalid_api_base_url`. Це захищає від різних API у Rust-клієнті та плагіні, який використовує фіксований cloud endpoint.
- IsConnected і LastError читаються зі спільного актуального стану. Done завершує фонові потоки до повернення; після Done об'єкт не приймає нові команди.
- Журнали DLL і UI за замовчуванням вимкнені. EnableLog/DisableLog застосовуються також до поточного UI; файли UI мають суфікс сесії. Один файл обмежений 5 MiB та однією резервною копією. Довільний текст console_log не записується. Logger DLL спільний для об'єктів цієї DLL у процесі.
- Очікування відповіді BAS на дію меню: 30 секунд, максимум 128 незавершених дій. Зміна чату/конфігурації відхиляє старі Promise.
